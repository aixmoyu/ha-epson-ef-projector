# 危险参数变体用「不实现」屏蔽

## 原则详细描述

同一固件命令常带多个参数变体，其中少数是破坏性的。本模块的处理不是校验入参，而是**让产生该参数的代码路径根本不存在**，并在 docstring/常量注释里留下"为什么不做"的记录。共四个实例：

|危险变体|后果|屏蔽方式|证据|
|-|-|-|-|
|`SET_REFRESH "1"`（size=1）|立即开始刷新并关机（`RefreshModeActivity` 发完即 `PowerManager.shutdown`）|`set_refresh_timer` 只拼 `f"0 {hours}"`，方法内不存在 `"1"` 分支|`api.py:481-488`（docstring 三次警告），`const.py:50-52`（说明 refresh 已从 `WRITABLE_SWITCHES` 移除），`number.py:150-152`|
|`SET_AMBIENT_LIGHT "255"`（size=1）|恢复氛围灯出厂设置，清空用户光效配置|三个写方法只产生 `"3 <0\|1> 48"`、`"4\|5 <0\|1>"`、`"9 <0-255> 48"`、`"1 <mode> 48"` 四种形状|`api.py:387-418`，`const.py:146-149`|
|光效槽 11|小程序临时预览配置，会覆盖用户光效|`AMBIENT_MODE_OPTIONS` 只列 3–6；`set_ambient_mode` 直接拼 `int(mode_id)` 且无校验，但唯一调用方传的是那张表|`const.py:158-163`，`select.py:205-215`，`api.py:411-418`（docstring 明示"slot 11 … deliberately not exposed"）|
|ESCVP 工厂写命令|MCU 串口透传可进入工厂态|只暴露 `AGPATTERN 01/00` 两条（开/关测试图案），完整码表 00–19 不实现|`api.py:420-430`，`const.py:179-183`（"完整码表 00-19 见工厂应用,其余图案视觉语义未确认,只暴露开/关"）|

另有两个"已删种"的历史痕迹：`engine_refresh` 按钮（`NOTIFY_APP_REFRESH`）被移除，因为它只是刷新确认应用的启动标记、单独发送无任何动作（`button.py:41-44`）；`refresh` 从 `WRITABLE_SWITCHES` 移除，因为把它当 0/1 开关是错的（`const.py:50-52`）。

## 为什么要这样

- **"不实现"比"校验"更可靠**：没有任何正常调用路径能产生危险参数，就不存在"校验被绕过"的问题。这是把安全边界建在**类型/接口形状**上，而不是运行时判断上——与"用类型消灭状态"同源。
- **现场分析工程语境的必然选择**：本模块的全部能力来自固件现场分析（`const.py` 里密集的"第 N 轮确认""真机实测"注释）。对未验证语义的参数，唯一负责任的做法是不暴露。`const.py:146-149` 与 `:171-172` 明确区分"已回环验证"与"未确认"，后者不进入公开 API。
- **知识必须留在代码里**：屏蔽不是删掉了事，而是把"这个参数存在且危险"写进注释。`api.py:483-487` 用 ⚠️ 标记并说明后果，使下一个人不会"顺手补上"。
- **为什么不加运行时白名单**：模块没有配置层、没有策略对象，加白名单需要引入一张命令/参数表，而这张表的维护成本高于收益——直到 `request()` 被直接调用这个事实出现（见"边界"）。

## 适用范围

- `custom_components/epson_ef/api.py` 全部命令方法。
- `const.py` 中承载"取值域"与"参数模板"的常量（`AMBIENT_MODE_OPTIONS`、`TEST_PATTERN_ON/OFF`、`WRITABLE_*` 表）。
- **不覆盖**：`request()` 公开透传路径（`services.py:64`）、`tests/` 中为确认语义而故意构造危险参数的用例。

## 规则

1. 新增命令方法前，先枚举该命令的全部已知参数变体，标注"安全/破坏性/未确认"。
2. 破坏性与未确认的变体：不写进方法，写进 docstring 的 ⚠️ 段落并给出后果与来源。
3. 参数模板必须**唯一确定**：一个写方法只允许产生一组参数形状，不得接受自由字符串（对照 `set_ambient_light` 用 `kind` 分支而非裸 params，`api.py:387-398`）。
4. 若某变体已被验证为安全但不常用（如 `focus_step` 的 INC/DEC），可以暴露，但必须在 docstring 说明它与推荐路径的关系（`api.py:516-527` 明确"绝对定位请用 goto_focus"）。
5. 值的钳制（如氛围亮度 0–255）必须在模块内完成，不得依赖调用方（`api.py:408` 是范例）。

## 反模式 / 禁止项

- ✗ 提供 `set_refresh(mode: str)` 这类透传签名，把参数正确性交给调用方。
- ✗ 在方法里 `if params == "255": return` 这种运行时黑名单——它掩盖了"为什么"，且没有覆盖 `request()` 直调。
- ✗ 把未验证的工厂命令作为"高级功能"暴露，仅用文档警告。
- ✗ 删除危险变体的注释记录（只删代码不留原因），会让下一个人重新踩坑。
- ✗ 用 `# noqa` 或注释掉代码的方式"屏蔽"——注释掉的代码仍会被搜索到并复活。

## 修改检查清单

- [ ] 新方法是否只产生**唯一确定**的参数形状？
- [ ] 该方法对应的命令族是否有已知危险变体？是否在 docstring 写了 ⚠️ 与后果？
- [ ] 数值参数是否在模块内钳制（参照 `api.py:408`）？
- [ ] 是否新增了 `request()` 的直调点？若有，是否评估过绕过风险（见 `risk.md` R-T08/R-T09）？
- [ ] 是否在 `const.py` 同步了取值域常量与解释注释？
